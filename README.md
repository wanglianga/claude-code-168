# 农村集市摊位抽签收费食品留样与投诉平台

面向乡镇集市的全流程管理平台：**报名 → 审核 → 公开抽签 → 收费/保证金 → 扫码入场 → 巡查 → 食品留样 → 投诉处置 → 信用与复盘**。
在“公开公平”与“现场灵活（雨天调位、费用减免、扣罚）”之间，通过**公示随机种子、逐条调整台账、审计日志**实现全程可追溯。

- 技术栈：Vue 3 + Element Plus + Vite；Spring Boot 3.2（JDK 17）+ Spring Data JPA；PostgreSQL 15；ZXing 二维码；Nginx 反向代理。
- 交付物：**一键启动** 的 `docker-compose.yml`（前端 80 / 后端 8080 / PostgreSQL 5432）。

## 一、功能与业务闭环

| 环节 | 功能点 |
|---|---|
| 赶集报名 | 经营品类、车辆/摊棚尺寸、用电需求与功率、是否熟食/活禽、证照照片、历史经营记录 |
| 报名审核 | 熟食必须有健康证/备案照片；核实历史赶集次数（老摊主优先依据）；通过/驳回（驳回原因可反馈，补齐后可重新报名） |
| 组织抽签 | 分区（普通干货/熟食冷链/活禽隔离）、消防通道禁明火熟食与活禽、尺寸匹配、带电源摊位匹配、老摊主+信用优先；**当场公示随机种子，结果可复算**；不符合条件进候补并写明原因 |
| 抽签结果 | 摊位号、错峰入场时间、摊位费/用电费/保证金、禁止事项；生成入场核销二维码 |
| 收费 | 缴费到账确认（未缴清不能入场）、困难/政策**费用减免**（必填理由+来源）、保证金**扣罚/退还** |
| 扫码入场 | 工作人员扫核销码核对身份/摊位/缴费，**必须拍摄摊位布置照片**才能完成入场 |
| 市场巡查 | 卫生、明码标价、缺斤少两（计量）、占道、用电安全五项评分；问题标签、现场照片、责令整改 |
| 食品留样 | 卤味/糕点/凉菜摊主上传留样照片、批次号、保存位置、冷藏温度；管理端留存覆盖率风险提示 |
| 投诉处理 | 腹泻疑似食物中毒/缺斤少两等登记与证据；办结可联动保证金扣罚+信用扣分，自动进入公示台账 |
| 临时调位 | 雨天积水、边界纠纷、消防需要等；目标摊位须空闲且仍满足分区/用电/消防/尺寸约束；**理由与来源必填** |
| 信用管理 | 信用分初始 100，所有加减分必须说明来源与理由，进台账并影响下一场抽签优先级 |
| 调整公示台账 | 临时调位、费用减免、保证金扣罚/退还、信用调整逐条公示：调整前后、金额、来源单据、理由、经办人 |
| 乡镇复盘 | 高投诉品类/投诉类型、违规与拥堵高发区域、收费到账率与待收、保证金扣罚、熟食留样覆盖率、腹泻投诉与食安风险等级 |
| 审计日志 | 登录、审核、抽签、状态流转、收费、入场、投诉处置等关键操作自动留痕 |

### 抽签规则（核心可追溯设计）

1. 活禽 → 活禽隔离区；熟食/凉菜/糕点 → 熟食冷链区；其余 → 普通干货区。
2. 邻近消防通道的摊位不安排熟食明火与活禽。
3. 申报车辆尺寸须与摊位匹配（0.2 米容差）；需用电摊主只能分配带电源摊位。
4. **优先级 = 历史赶集次数 × 3 +（信用分 − 100）**，优先级高者先抽；同优先级比随机数（小者先抽）。
5. 随机数由 `SHA-256(集市ID + 当场公示种子)` 确定性产生；同种子同报名名单，结果完全一致，可供乡镇、摊主复算核对。
6. 无符合摊位者进**候补**，并注明具体原因（区域抽满 / 尺寸超出 / 带电摊已满）。
7. 抽签后不允许人为改摊位；确需现场调整只能走“临时调位”，目标摊位受同样规则约束且全程公示。

## 二、一键启动（推荐，Docker Compose）

前置条件：已安装 Docker 与 Docker Compose（或 Docker Desktop）。

```bash
cd /workspace/168-a
docker compose up -d --build
```

- 前端（操作入口）：http://localhost
- 后端 API：http://localhost:8080/api/health
- 首次启动自动建表并写入演示数据（2 个集市、12 个账号、一个含完整业务链路的已结束集市）。
- 停止与清理：

```bash
docker compose down          # 停止
docker compose down -v       # 同时清空数据库与上传文件卷
```

> 上传的证照/布置/留样/证据图片保存在 Docker 卷 `uploads`（容器内 `/app/data/uploads`）。

## 三、本地开发启动（不用 Docker）

### 1) 准备 PostgreSQL

```sql
CREATE USER market WITH PASSWORD 'market' CREATEDB;
CREATE DATABASE market_fair OWNER market;
```

### 2) 启动后端（端口 8080）

```bash
cd backend
# 方式 A：使用本地 PostgreSQL（默认连 localhost:5432/market_fair）
mvn spring-boot:run

# 方式 B：临时免数据库体验（H2 内存库，自动建表+种子数据）
SPRING_PROFILES_ACTIVE=h2 mvn spring-boot:run
```

可通过环境变量覆盖：`JDBC_URL`、`JDBC_USER`、`JDBC_PASSWORD`、`UPLOAD_DIR`、`SERVER_PORT`。

### 3) 启动前端（端口 5173）

```bash
cd frontend
npm install
npm run dev
```

打开 http://localhost:5173 ，Vite 已将 `/api`、`/uploads` 代理到 `http://localhost:8080`。

生产构建：`npm run build`，产物在 `frontend/dist`（Docker 镜像中由 Nginx 托管并反向代理 API）。

## 六、已执行的验证结论（仅记录实际执行过的验证）

- 后端 `mvn package` 构建成功；Spring Boot 对 PostgreSQL 启动、自动建表、种子数据初始化成功。
- 通过 API（curl）实际验证通过的链路：
  - 登录鉴权与角色权限（摊主不能抽签/看审计/查看他人抽签结果，未登录返回 401）；
  - 报名审核（熟食无证照不能通过、可驳回；驳回后补齐证照重新报名的入口保留）；
  - 公示种子抽签可复算，且区域/消防/用电/尺寸/老摊主优先级规则生效（含候补原因）；
  - 未缴清费用拒绝入场、超额缴费拒绝、收费到账状态流转；
  - 扫码入场（无布置照片拒绝）、食品留样必填校验、巡查五项评分落库；
  - 投诉登记→办结→保证金扣罚+信用联动扣分（105→75）→公示台账；
  - 扣罚超余额拒绝、无理由扣罚/减免拒绝；
  - 雨天同区调位成功、占用摊冲突拒绝、熟食/活禽跨区调位拒绝；散场保证金退还；
  - 复盘统计接口输出与种子事实一致（到账率、扣罚、投诉品类、留样覆盖率、风险等级）。
- 前端 `npm run build`（Vite 生产构建）通过；Dockerfile / docker-compose.yml / nginx.conf 已提供。
- 当前隔离环境未安装 Docker 守护进程，**未在本机实际执行 `docker compose up`**；容器构建配置已按多阶段构建给出，需在具备 Docker 的环境执行验证。
